# Контроль качества продукции: статистические отчёты

Набор из пяти Jupyter-ноутбуков на R. По демонстрационным данным они проходят путь от сырых измерений до точности прогнозных оценок.

Ячейки уже выполнены: таблицы и графики сохранены внутри `.ipynb`.

---

## Зачем это репозиторий

Проект отвечает на четыре практических вопроса:

1. Можно ли подавать сырые измерения в модель как есть?
2. Как связаны прогнозные оценки, индексы и категории изделий?
3. Что меняется, если оставить только точные оценки?
4. Чем объясняется точность оценки — измерениями, серией, годом, сертификацией или связанными позициями?

Тема нарочно нейтральная: **контроль качества продукции**. В данных нет отраслевых идентификаторов, только производственные показатели.

## Что внутри отчётов

| Файл | Вопрос | Данные | Методы |
|---|---|---|---|
| **01** Подготовка | Есть ли выбросы, неоднородная дисперсия, коллинеарность? | `metric_output.csv` | z-score, Андерсон–Дарлинг, Levene, VIF, Краскел–Уоллис, Данн, Дарбин–Уотсон |
| **02** Оценки | Как связаны оценки, индексы и категории? | `scores.csv` | Кендалл, Шапиро–Уилк, ANOVA / Краскел–Уоллис |
| **03** Точные оценки | Что остаётся, если `accuracy ≥ 0.8`? | `scores_accuracy.csv` | те же тесты на отфильтрованной выборке |
| **04** Регрессия | Что двигает индексы? | `scores_norm.csv`, `metric_averages.csv` | линейная регрессия, центрирование, `glinternet` |
| **05** Точность | От чего зависит надёжность оценки? | измерения + `scores_accuracy.csv` + `registry.csv` | гистограммы, boxplot, Манна–Уитни, регрессия по категориям |

### Показатели

| Код | Смысл |
|---|---|
| `output` | производительность |
| `related` | сопутствующий выпуск |
| `frequency` | частота выпуска |
| `yield` | выход годного |
| `volume` | объём партии |
| `defect` | доля брака |
| `overall_index` | сводный индекс |
| `process_index` | индекс процесса |
| `product_index` | индекс изделия |
| `rel_*` | точность соответствующей оценки |

Категории изделия: тип (`A` / `B`), год выпуска, серия, класс, площадка, марка, метод изготовления, сертификация.

## Как пересобрать

Нужны **R 4.x**, пакеты ниже и **Python 3** (`json`).

```r
install.packages(c(
  "dplyr", "tidyr", "ggplot2", "nortest", "e1071", "car", "MASS",
  "FSA", "nlme", "lmtest", "sandwich", "fixest", "glinternet",
  "jsonlite", "evaluate", "base64enc"
))
```

Из корня репозитория:

```bash
Rscript data/generate_data.R
Rscript execute_notebooks.R
```

Первая команда пишет CSV в `data/`. Вторая заново выполняет все ячейки и сохраняет вывод в ноутбуках.

Демо-данные синтетические (`set.seed(42)`), чтобы репозиторий был самодостаточным. Скрипт генерации можно заменить своими выгрузками с теми же именами столбцов.

## Данные

| Файл | Содержание |
|---|---|
| `metric_output.csv` | измерения производительности (для диагностики и флага «есть факт») |
| `metric_related.csv` … `metric_defect.csv` | измерения остальных контуров |
| `scores.csv` | оценки, индексы, категории |
| `scores_norm.csv` | то же для регрессии |
| `metric_averages.csv` | средние измерения, стыкуются по `item_id` |
| `scores_accuracy.csv` | оценки плюс коэффициенты точности `rel_*` |
| `registry.csv` | соответствие `rec_id` ↔ `item_id` для связанных позиций |
